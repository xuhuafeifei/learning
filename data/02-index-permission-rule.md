# 索引权限：能读到就能建

语义索引的构建权限只有一条规则：只要当前用户有权限读到这篇文章，就有权限为它构建向量。不需要是作者，不需要是管理员，读权限即索引权限。

这条规则落在重建入口的逐篇校验上：传入一批文档 ID，每一篇单独过读权限检查，能读的进入重建流程，不能读的不会被报错拒绝，而是安静地进到"跳过"名单里随响应返回。也就是说，一次批量重建混合了有权限和无权限的文档时，结果会分成三类：成功的、跳过的、失败的（失败通常意味着模型没就绪或者正文读取出了问题）。

单次批量重建的上限是一百篇，防止一次请求把推理线程占死。

同一个能力暴露了两条路：HTTP 接口给设置页的管理界面用，Agent 工具给对话助手用。两条路调的是同一个服务层函数，权限口径完全一致——工具没有任何特权，也不是绕过 HTTP 再查一遍，它拿到的访客身份和浏览器请求是同一个。

配套还有一个状态查询：列出当前用户可读的所有 Markdown 文档，标注每篇的向量块数量和上次构建时间，用来判断哪些文章还没建索引。
