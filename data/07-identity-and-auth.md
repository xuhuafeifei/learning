# 身份与鉴权的优先级

系统没有账号体系，访客身份靠三层凭证之一确认，优先级从高到低是：Cookie、CLI 专用头、通用访客令牌头。

Cookie 是浏览器侧的默认通道，HttpOnly，页面脚本摸不到，自动随请求带上。命令行工具没有 Cookie，用自己专属的头标明身份，方便本地脚本和 Agent 调用。最后兜底的是通用访客令牌头，最早期的通道，现在主要留给兼容场景。三层按顺序解析，命中任意一层即确认身份，都失败则一律拒绝，不区分是哪层没带上。

服务端永远只存令牌的 SHA-256 哈希，明文令牌只存在于用户浏览器本地存储和 Cookie 里。所以令牌丢了只能重新注册身份，没有找回一说。

对话助手的工具不走 HTTP 通道：访客身份由调用方依赖注入，工具函数直接调用服务层，省掉序列化和端口开销，但权限校验一字不少——工具能读什么，取决于注入的是谁的身份，而不是"工具"这个调用方式本身。
